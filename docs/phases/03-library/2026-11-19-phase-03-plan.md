## Proposed implementation slice (for a later IMPLEMENT chat)

1. **Identity registry, not printed-number routing.** Give every candidate an immutable opaque public ID (`q-<frozen short key>`) assigned once in a checked, versioned registry; the printed `Q72` stays a separate display field. Include year, paper/stream, booklet set/series, category, printed section/number, source page/URL, figure status, rights/readiness, provenance, review date, topic IDs, primary section anchor, answer provenance and aliases for old slugs. Derive a fingerprint from the full source coordinates to detect accidental reuse, then freeze the assigned ID. A build check must fail when two different source records produce the same ID or when an ID changes between revisions; two streams that both print Q72 must resolve to two different pages.
2. **Reader content and honesty.** A public route renders only a record with documented permission and a reviewed readiness state. Show year/paper/set, printed number, category, marks, source, figure status and answer status without implying that a board key endorses our solution. A held or unknown ID returns 404 in `dist/`; no draft record, private PDF or archive asset is emitted. Held editorial records stay in the evidence phase.
3. **One reviewed mapping, two directions.** Keep forward links (including the one primary anchor) in the reviewed question record; generate lesson backlinks from that same record at build time. Validate that every target anchor exists in the named lesson and has a recorded relevance review before publishing it. If there is no relevant section, render the exact state “Lesson not mapped yet” and keep the question permalink; never open a generic chapter or invent a topic match. The existing lesson has **no** primary PYQ IDs, so today it must show no PYQ backlink; the clearly labelled original independent case is the only stand-in.
4. **Return path.** Create base-aware `/q/<id>/` pages (`import.meta.env.BASE_URL`, no absolute-site URLs), with a canonical URL recorded per environment. “Learn this concept” links to the exact anchor; a visible “Back to question” works without JS. For the JS path, preserve the originating question ID and allowlisted filter values in validated query parameters or history state, so Back restores the same question and filters on a fresh device. Query values are display filters only: no bookmark, note, chosen option, identity or local-storage key is written into a shared URL. Invalid parameters are ignored, not interpolated into HTML.
5. **Synthetic fixtures only (test data, not editorial claims).** Proposed build fixtures: two different streams both printing `Q72` with distinct frozen IDs; one held record with no public route; one mapped record whose target anchor is missing (build must fail); one unmapped permitted record showing “Lesson not mapped yet”; an old slug alias resolving once; and a direct `/Jelet-ultimate-prep/q/<id>/?filter=category-2` load followed by anchor → Back → same filters. These identifiers and filters are placeholders for validation, never evidence that a real question is cleared or mapped.
