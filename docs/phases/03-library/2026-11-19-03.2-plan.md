## Proposed implementation slice (for a later IMPLEMENT chat)

1. **Build-time local index.** Generate a small static index from already-reviewed records: `{id, type: lesson|question|sheet, title, topic IDs, year, paper/set, category, readiness, figure flag, canonical base-aware URL, section anchors}`. Group results by type. Load on demand from a relative URL; no remote request, account, API key or analytics. Normalize whitespace and option prefixes (`A.`, `(A)`), preserve meaningful signs, exponents, subscripts and units (`10^-3`, `R₁`, `Ω`, `½`); do not flatten them into a wrong number. Held and draft records are excluded, not shown as “coming soon” public results.
2. **Result presentation.** Show year, paper and printed number next to each question candidate so the student can confirm identity; show the exact section for a lesson. An empty query returns a short explanation and a “broaden filters / enter year or number” action, not a blank panel. Manual filters mirror [UI reference](../../UI_REFERENCE.md): subject/topic, year, stream, category, readiness and figure availability. Filters are local UI state only.
3. **Share tiers.** Default public share contains identity metadata and the canonical base-aware question URL with **no answer, hint or solution**. An explicit “with solution” variant is generated only when a reviewed solution record exists for that exact ID; never for a held item or from a localStorage attempt. Use `navigator.share` when present, then `navigator.clipboard.writeText`, then a focusable, selectable text field with a copy instruction. Metadata and URL only — no screenshot and no private state.
4. **Recipient path.** A recipient opens the link on a clean device with no session: reader shows source/readiness, `Learn this concept` reaches the reviewed exact anchor (or the 03.1 “not mapped” state), and Back returns to the same question and allowlisted filter values. The share URL never embeds bookmarks, notes, choices or a resume flag; those stay in local state. In rehearsal (04) solution links remain hidden until submission.
5. **Synthetic fixtures (test data, not editorial claims):** two streams both printing Q72 with distinct IDs; one question without a reviewed solution (no solution variant offered); clipboard denied; `navigator.share` absent; direct subpath URL on a fresh context; noisy text that normalizes to a candidate; blank query. No fixture asserts a real question is cleared or mapped.
