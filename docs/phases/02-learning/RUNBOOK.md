# 02 field guide · ship one vertical learning slice, not five empty menus

**Inputs:** approved phase 01 material, [product journey](../../PRODUCT.md) and [static architecture](../../ARCHITECTURE.md). All tasks are prospective, behind implementation approval.

1. **02.1 — Static skeleton.** Generate Today → Learn → chapter → addressable lesson section under the Pages project base. Apply shared semantic typography/focus tokens, render the text first, hydrate only interactive parts. Record dependency purpose and public output size. No backend for an interactive circuit.
2. **02.2 — Author the pilot.** Pair a labelled two-branch diagram with a prediction. Reveal why two 6 Ω resistors across 12 V draw 4 A together; then use a *different* case for independent practice. State ideal-source assumption. Add units, meaningful figure description, revision sheet and exact prerequisite link. An absent verified PYQ gets an original exercise label, never a fake year.
3. **02.3 — Notebook and media.** Start with steps hidden. Preserve place when backgrounded. A selected video needs purpose, timestamp and written alternative; don't autoplay. Omit unreviewed Bengali technical claims. Hint levels should reveal a relationship before revealing arithmetic.
4. **02.4 — Transfer check.** From a narrow phone open a cold link, enlarge the figure, finish the task and return after locking the screen. Ask a learner to explain a later unseen variant; note only anonymized observations and consent. Inspect with keyboard, enlarged text and JS disabled (lesson remains readable).

**Outputs:** one working chapter URL/path, authored records, dependency/build report and test observations. Distinguish “pages render” from “student demonstrated transfer.” If student review is unavailable, record not tested, not a learning success. Don't expand chapters to conceal a weak first lesson.
