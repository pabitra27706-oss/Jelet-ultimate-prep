# 12 · Release verification and owner correction loop

**Status · 2026-11-20:** planned, not executed.
**Entry:** Phase 11 tested candidate, audit disposition, rights reference and owner-approved display/scoring scope.
**Exit:** a bounded release with truthful labels, Android/offline evidence, rollback instructions and an exercised correction route. Unfinished evidence remains unfinished in the roadmap.

This phase implements the existing owner-practice loop; it does not introduce analytics, accounts, a feedback backend or a new curriculum track. Cost ceiling remains ₹0, without new accounts, sign-ups, trials or paid services.

## Release boundary

A read-only provisional release may be approved separately from a verified-scoring release. Publish exactly which years/items and which mode are covered. No “complete key”, “board verified” or modern-syllabus coverage claim follows from publishing old-paper answer aids.

## Owner correction loop

Owner practises → records question/stream/key revision and observation → reviewer traces the source → adjudicates → records correction → authorised update and retest → release notice. Keep personal practice notes private; publish only a sanitised content correction and evidence that is cleared for publication. No automatic collection of visitors' work.

A suspected wrong answer is withheld from scoring pending review. Never quietly replace a letter, erase an earlier reason, or recompute a past submitted attempt. If no user reporting surface is approved, use the existing manual report route and state that limitation.
