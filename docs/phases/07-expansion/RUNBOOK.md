# 07 field guide · repeat a chapter-sized editorial batch

1. **07.1 Select a gap.** Use the coverage inventory and reported student difficulty to choose one chapter and a specific learning outcome. Record what it adds and what remains uncovered. Keep the batch small enough for a reviewer to personally check every new learning objective.
2. **07.2 Author and map.** Reuse the [lesson worksheet](../../templates/lesson.md) per lesson. For each linked PYQ explain why the anchored section teaches it. Technical reviewer compares any Bengali explanation with the English quantities and signs. Reject a video with no useful segment or written alternative.
3. **07.3 Generate only where justified.** With build-time Python, document template equation, allowed ranges, exclusions, units, seed and version. Check boundary values, unique options and that rounding never produces two valid choices. Independently solve samples including range endpoints. Label generated items original exercises. A large item count is not evidence of coverage.
4. **07.4 Release and learn.** Test one guided-to-independent sequence and later transfer task. Publish coverage delta, held IDs, corrections and task outcomes per batch. Recheck deployed bytes and examples on a narrow phone. Only use “full mock” after phase 05's separate whole-paper gate.

**Decision:** release verified pieces; defer an unreviewed translation or generator rather than blocking the text lesson. Stop growing a batch if the review backlog or download size grows faster than its useful coverage.
