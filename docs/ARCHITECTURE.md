# Architecture and study data

**Build:** Markdown lessons + schema-checked question records → link/rights/readiness checks → Astro prebuilt routes with TypeScript strict and Tailwind CSS → static assets on GitHub Pages. Optional build-time Python for corpus audits, deterministic numeric variants and search indexes. No student request runs Python. Self-host required maths/fonts and load search by demand. Ship readable pages and links without JS; attach JS for practice, local storage and interactive labs. Generate only approved public assets; check output for archives, private source files and backups.

**Pilot implementation (Phase 02):** Astro static output, a validated original Markdown lesson, strict TypeScript, and shared CSS tokens without Tailwind to keep this slice smaller. Native disclosure controls need no JS. The only local data is one versioned `localStorage` lesson record (section and hint/reveal flags); the IndexedDB contract below still applies to later workspace phases. The Pages project subpath is `/Jelet-ultimate-prep/`. PR checks build and inspect the artifact; they do not publish.

**Preview slices (Phase 03.1–03.4):** a second validated Markdown collection holds approved *original practice* items only, each with an immutable `orig-` public ID, source/readiness fields and one reviewed lesson anchor. A build-time guard rejects duplicate IDs, unknown anchors and non-original provenance; static reader and practice-index routes are generated at the project subpath, and lesson backlinks come from the same forward mapping. A small client-side check reveals an allowlisted origin/filter note. A build-time JSON index of those approved items drives same-origin grouped search with local query/filter state and a paste-only photo-discovery path; a native-share/clipboard/selectable-text chain shares only metadata and an absolute canonical URL. A versioned IndexedDB workspace stores bookmarks, notes and one resume pointer, with local JSON export, validated import preview, merge/replace/cancel and typed reset. No answer enters the URL, share payload or index keys; no personal export is committed. No public PYQ record, solution variant, real Lens service, cloud sync or full attempt/grading store exists yet.

**Stable addressing:** create one static page per public question and lesson with immutable section anchors. Build forward and reverse topic links from the same reviewed mapping. Base-aware URLs must work on a project subpath, including pasted links and refresh. No server rewrites required. Answer keys delivered to clients cannot be secret: this is preparation, not proctoring.

**Local data contract:** IndexedDB stores keyed bookmarks, notes, topic states, reading position, attempts, flags, due retries and settings. Attempt snapshot includes paper/set, rule and content versions, selected options, assistance, timestamps and submission state. Persist before navigating; resume from a deadline, not tick counts. Backgrounding, reload and opening two tabs must not award extra time or submit twice. Do not claim local clocks are tamper-proof. Show explicit unsaved state for blocked/full storage.

**Backup:** versioned JSON; validate type, supported version, size and IDs before preview. Explain merge vs replace, require confirmation, keep old data on cancel/error, dedupe by stable IDs, retain unresolved legacy entries for review. Do not claim old-site import works before a consented sample passes round trip. Exports are personal files, never repository fixtures. Manual transfer is not cloud sync. Clearing browser data may lose work; offer export and confirmed reset.

**Offline:** a pack manifest pins version, resources, figures and size. Only mark ready after all required files are saved. Keep prior complete pack on interrupted update; allow removal without deleting attempts. Handle low space, stale pages and offline fallback. YouTube and external Lens require their own services; local paste/search should not upload anything.

**Optional services:** no default analytics, identities, remote AI calls or photo uploads. Guest reading and drills survive every service outage. If sync is later justified, use hosted sign-in rather than collecting passwords; validate per-user isolation, guest merge, export/deletion and hard free quota before enabling. A live tutor would require server-side secret handling, opt-in, request limits, spending blocked and safe offline fallback. Do not place a secret in static assets or require the maintainer's phone to run a backend.
