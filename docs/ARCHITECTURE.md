# Architecture and study data

**Build:** Markdown lessons + schema-checked question records → link/rights/readiness checks → Astro prebuilt routes with TypeScript strict and Tailwind CSS → static assets on GitHub Pages. Optional build-time Python for corpus audits, deterministic numeric variants and search indexes. No student request runs Python. Self-host required maths/fonts and load search by demand. Ship readable pages and links without JS; attach JS for practice, local storage and interactive labs. Generate only approved public assets; check output for archives, private source files and backups.

**Pilot implementation (Phase 02):** Astro static output, a validated original Markdown lesson, strict TypeScript, and shared CSS tokens without Tailwind to keep this slice smaller. Native disclosure controls need no JS. The only local data is one versioned `localStorage` lesson record (section and hint/reveal flags); the IndexedDB contract below still applies to later workspace phases. The Pages project subpath is `/Jelet-ultimate-prep/`. PR checks build and inspect the artifact; they do not publish.

**Preview slices (Phase 03.1–03.4):** a second validated Markdown collection holds approved *original practice* items only, each with an immutable `orig-` public ID, source/readiness fields and one reviewed lesson anchor. A build-time guard rejects duplicate IDs, unknown anchors and non-original provenance; static reader and practice-index routes are generated at the project subpath, and lesson backlinks come from the same forward mapping. A small client-side check reveals an allowlisted origin/filter note. A build-time JSON index of those approved items drives same-origin grouped search with local query/filter state and a paste-only photo-discovery path; a native-share/clipboard/selectable-text chain shares only metadata and an absolute canonical URL. A versioned IndexedDB workspace stores bookmarks, notes and one resume pointer, with local JSON export, validated import preview, merge/replace/cancel and typed reset. No answer enters the URL, share payload or index keys; no personal export is committed. The original practice card moved from `/practice/[id]` to `/cards/[id]` when the PYQ drill routes took over `/practice/`, so the two never collide.

**Exam engine (Phase 04 upgrade, 2026-11-19):** `scripts/build-content.mjs` is a deterministic generator that parses the preserved corpus in `archive/jelet-prep/data` into `src/data/papers.json`, `src/data/keys.json` and `src/data/syllabus.json`. It refuses to emit a scoreable item without four parsed options, a key and a year-specific rule, so unverified or incomplete questions cannot enter a scored pool; they stay readable with their hold reason. `src/lib/scoring.ts` does the marking in exact rational arithmetic (`{n, d}`), never floating point: Category I awards +1 only for exactly one correct choice and −¼ otherwise, Category II awards +2 for all correct choices, 0 when any wrong choice is marked, and `2 × correct marked ÷ total correct` for a correct subset, and a board-voided item awards its full marks. `src/lib/runner.ts` is a client-side engine over server-rendered question panes; it reads each item's category, marks and subject from `data-` attributes on the pane, keeps the attempt in `localStorage`, and folds the result into the Leitner queue in `src/lib/review.ts`. `src/lib/stats.ts` derives coverage, accuracy, streak and subject breakdowns from real attempts only. The key file is served as a static, tier-labelled JSON document; it cannot be secret, because this is preparation, not proctoring.

**Composed sets (2026-11-19):** `src/lib/mock.ts` holds one specification for a set - subjects, topics, length, category mix and seed - and `src/lib/mock.ts`/`src/lib/mock-client.ts` draw the questions from the same server-rendered pools the paper reader uses, so a composed set is marked by the same `src/lib/scoring.ts` rules as a real paper. The specification travels in the query string, which makes a set a link: bookmarkable, shareable and always the same set. A deep link into the builder now opens on the selection it carries, and a topic may be named by its id (`mathematics-td`) or by its code (`td`); a code is resolved inside each chosen subject, and a parameter that is absent falls back to the default rather than to zero. `/mock/run/` is the timed form with a clock and a navigator; `/quiz/` is the notebook form - one question at a time, no clock, marked the moment the learner checks it, with the published key and the paper it came from shown at once, and the place kept on the device. A quiz is a real attempt: it counts towards coverage and accuracy, and the questions it was wrong on wait for revision like any others. `src/lib/remediation.ts` counts a learner's mistakes by syllabus topic and by their own reason tag, and `src/pages/plan/` assembles those into one lesson, two problems and one repeat.

**Static search:** `src/pages/search-index.json.ts` emits a compact v2 payload (short keys, 692 entries, 381,610 bytes raw and 59,073 bytes gzip) that the search page fetches once and matches in the browser. The no-JavaScript directory on the same page lists one entry per paper rather than all 690 questions.

**Offline shell:** `public/sw.js` is a same-origin service worker that precaches the shell, the key file and the search index, serves navigations from the cache when the network fails, and refreshes assets in the background. `public/manifest.webmanifest` plus the two icons make the site installable. Nothing outside this origin is ever requested; the browser suite fails the build if it is.

**Stable addressing:** create one static page per public question and lesson with immutable section anchors. Build forward and reverse topic links from the same reviewed mapping. Base-aware URLs must work on a project subpath, including pasted links and refresh. No server rewrites required. Answer keys delivered to clients cannot be secret: this is preparation, not proctoring.

**Local data contract:** IndexedDB stores keyed bookmarks, notes, topic states, reading position, attempts, flags, due retries and settings. Attempt snapshot includes paper/set, rule and content versions, selected options, assistance, timestamps and submission state. Persist before navigating; resume from a deadline, not tick counts. Backgrounding, reload and opening two tabs must not award extra time or submit twice. Do not claim local clocks are tamper-proof. Show explicit unsaved state for blocked/full storage.

**Backup:** versioned JSON; validate type, supported version, size and IDs before preview. Explain merge vs replace, require confirmation, keep old data on cancel/error, dedupe by stable IDs, retain unresolved legacy entries for review. Do not claim old-site import works before a consented sample passes round trip. Exports are personal files, never repository fixtures. Manual transfer is not cloud sync. Clearing browser data may lose work; offer export and confirmed reset.

**Offline:** a pack manifest pins version, resources, figures and size. Only mark ready after all required files are saved. Keep prior complete pack on interrupted update; allow removal without deleting attempts. Handle low space, stale pages and offline fallback. YouTube and external Lens require their own services; local paste/search should not upload anything.

**Optional services:** no default analytics, identities, remote AI calls or photo uploads. Guest reading and drills survive every service outage. If sync is later justified, use hosted sign-in rather than collecting passwords; validate per-user isolation, guest merge, export/deletion and hard free quota before enabling. A live tutor would require server-side secret handling, opt-in, request limits, spending blocked and safe offline fallback. Do not place a secret in static assets or require the maintainer's phone to run a backend.
